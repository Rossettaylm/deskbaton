# DeskBaton 剪贴板实时同步设计

日期：2026-10-18　状态：已实现

主设计见 `2026-10-16-deskbaton-design.md`。本机设置见 `2026-10-17-panel-settings-design.md`。
本文取代 `2026-10-17-clipboard-design.md` 中关于**同步时机与参与交棒**的部分；内容格式、敏感标记、32 MiB 上限、不进 `config.toml` 仍沿用该文。冲突时以本文为准。

主设计第 2 节「预留：剪贴板实时同步」提前到本轮实现。交棒不再附带剪贴板。

修订（2026-10-18）：去掉面板「剪贴板」tab 与「剪贴板页」「未发上限」旋钮。实时同步、总开关、发件箱逻辑不变。`clipboard_tab` / `clipboard_outbox_limit` 仍留在 `state.toml`，以免 `deny_unknown_fields` 拒读旧文件。

## 1. 目标

本机一复制，已配对且在线的对端系统剪贴板立刻变成同一份文本或图片。对端没在线（睡着、没开 agent、掉线）时，先放进发给**那一台**的发件箱；它上线后再按复制顺序送过去。面板不展示未发列表。

## 2. 范围

**做**

- 轮询系统剪贴板（约 500ms），发现本机新复制后同步
- 每个已配对对端一个发件箱；在线立刻发，离线入箱，上线按序冲刷
- 通道 `1` 仍用现有 transfer；`handoff_id` 固定为 `0`，不绑某次交棒
- 交棒时 `pack` 不再带剪贴板
- 防回传、不转发收到的内容、敏感跳过、超过 32 MiB 跳过
- 设置：总开关 `clipboard_sync`；每端发件箱上限 `clipboard_outbox_limit`（默认 10，启动时读取，面板不提供旋钮）

**不做**

- 面板「剪贴板」页、未发列表、图片灯箱
- 把 DeskBaton 做成剪贴板历史管理器（送成功的条目不留副本）
- 应用层 ACK、持久化发件箱到磁盘
- HTML / RTF / 文件列表 / 视频
- 系统剪贴板变更的操作系统推送 API（各平台不统一，首版轮询）
- 回写 `config.toml`、升 `PROTOCOL_VERSION`

## 3. 架构

不走交棒参与者的 `pack`。agent 里独立跑 `ClipboardBridge`：轮询、分发、冲刷发件箱。接收仍走现有 `Event::Data` → 通道 `1` 的 `unpack`（写入系统剪贴板）。交棒流程零改动。

```text
本机新复制
    → 每个已配对对端
        ├ 在线 → PeerLink.send_data(channel=1, handoff_id=0)
        └ 离线 → 该对端发件箱（FIFO，上限 N）
对端上线 → 只冲刷它的发件箱

对端 unpack → 写系统剪贴板，哈希进入防回传集合
              不向第三人转发
```

| 位置 | 职责 |
|---|---|
| `baton-core` | `ClipboardAccess` 等端口不变；`LocalState` 保留 `clipboard_sync`、`clipboard_tab`、`clipboard_outbox_limit`；发件箱纯逻辑（假时钟可单测） |
| `baton-clipboard` | 系统读写；`ClipboardSync.pack` 恒为 `None`，`unpack` 仍写系统剪贴板；`ClipboardBridge` 轮询与分发 |
| `baton-agent` | 注入 bridge；对端上线 / 下线 / 取消配对通知它；总开关仍是进程内 `AtomicBool` |
| `baton-gui` | 设置里的总开关 |

`baton-core` 仍不依赖 `clipboard-rs` 或系统 API。

`send_data` 排队成功即视为该条已离开发件箱。传输中途断线不补发、不升协议做 ACK；对端上线后只送**当时还在箱里**的。风险见第 9 节。

## 4. 发件箱

键：对端证书指纹（配置里只有名称、没有档案的对端用 `DeviceId`）。新配对从空箱开始；`PeerRemoved` 丢掉该箱。进程退出发件箱丢弃，不写磁盘。

本机出现一份**可同步的新内容**（见第 5 节）时，对每个已配对对端：

1. 在线且 `send_data` 入队成功 → 不入箱。
2. 否则追加到该对端箱尾。超过 `clipboard_outbox_limit` 丢掉最旧一条，不提示。

对端变为在线：按从旧到新依次 `send_data`；入队成功则从箱头拿掉；失败则停下，留着等下次上线。

只发本机产生的复制。`unpack` 写入的内容把哈希记入防回传集合，轮询读到同一份既不发送也不入箱，因此 A→B、A→C 之后 B 不会把 A 的内容转给 C。

## 5. 内容

与 2026-10-17 第 4 节相同，读的顺序：

1. 敏感约定标记 → 跳过，不入箱，不提示。
2. 有图片 → `image/png`。
3. 否则有文本 → `text/plain`（UTF-8）。
4. 空、读失败、`Unsupported`、超过 32 MiB → 本次忽略；超限提示「剪贴板过大，未同步」。

同时有图和字只传图。

线上仍是一条 `Payload { format, data }`。`handoff_id` 为 `HandoffId(0)`。协调器按「交棒已中止则丢弃同 id 的数据」处理时，真实交棒 id 是时间戳，不会误删 `0`。

防回传：记住最近发出和写入的内容哈希（`format` + 字节的 SHA-256），集合上限 32 条，超出丢最旧。不能只记「上一条」：冲刷多条时对端写入第一条就会被自己的轮询看见。

敏感标记仍只认：

| 平台 | 类型名 |
|---|---|
| macOS | `org.nspasteboard.ConcealedType` |
| Windows | `ExcludeClipboardContentFromMonitorProcessing` |

## 6. 设置与面板

用户只在「设置」改总开关。写入 `state.toml`，缺省如下，继续 `deny_unknown_fields`，走读-改-写。

| 项 | 字段 | 默认 | 作用 |
|---|---|---|---|
| 剪贴板 | `clipboard_sync` | 开 | 关：不采集、不发送、不写入对端送来的内容；发件箱冻结（不清空） |
| （兼容）剪贴板页 | `clipboard_tab` | 开 | 旧文件仍能读；面板不再读写 |
| （兼容）未发上限 | `clipboard_outbox_limit` | 10 | 启动时裁箱；合法范围 1–50，非法值当 10；面板不提供旋钮 |

体积上限仍是代码常量 32 MiB，不进面板。

无界面 `deskbaton` 读同样的 `clipboard_sync` 和上限。

面板三个 tab：显示器 / 设备 / 设置。不渲染剪贴板页，不订阅发件箱变化。

## 7. 失败

同步失败不得阻断或拖慢交棒。提示走现有 `Notifier`（受「通知」开关约束）。

| 场景 | 处理 |
|---|---|
| 读失败 / 空 / `Unsupported` | 忽略，只记日志 |
| 敏感标记 | 忽略，不提示 |
| 超过 32 MiB | 不发不入箱，提示「剪贴板过大，未同步」 |
| 对端离线 | 入该对端发件箱 |
| `send_data` 失败 | 留在箱里 |
| 对端关掉同步 | 发送方照常送；接收方 `unpack` 不写 |
| 写入系统剪贴板失败 | 日志 + 提示「未能写入剪贴板」 |
| 不认识的 `format` | 丢掉，只记日志 |
| 传输中途断线 | 已出箱的不补发 |

## 8. 测试

- 发件箱（假对端、假链路）：在线直发不入箱；离线入箱；上线按序冲刷；超上限丢最旧；取消配对丢箱；不转发「刚收到」的内容；防回传集合挡住冲刷引起的回声。
- `pack` 恒为 `None`；`unpack` 仍写系统剪贴板，且受总开关约束。
- `state.toml`：新字段缺省、非法上限当 10、改其它偏好不丢 `clipboard_sync` / `clipboard_tab` / `clipboard_outbox_limit`。
- 协调器现有交棒测试不动。回环：在线复制对端能粘贴；假离线再上线后发件箱清空且对端收到。
- CI 不碰真实系统剪贴板。

硬件验收（手动，🔧，用户确认后才打勾）：

1. 两台都在线：本机复制文字 / 截图，对端立刻能粘贴，不必切换电脑。
2. 关掉对端 DeskBaton 后本机复制若干条；对端再开，能粘贴最后一条，系统剪贴板历史里能看到冲刷进去的若干条。
3. 关掉总开关后再复制，对端不变。
4. 密码管理器复制（带敏感标记）不同步。
5. 切换电脑期间复制失败或超限，画面和键鼠仍能切过去。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 多台共用一个队列、先醒的清空 | 按对端分箱，见第 4 节 |
| 收到后再转发出去形成 A→B→C→A | 不转发；哈希集合而不是只记上一条 |
| 新配对设备吃到旧剪贴板 | 新配对空箱 |
| `send_data` 只保证入队 | 不补 ACK；断线丢失已出箱的条目，见第 7 节 |
| 轮询 500ms 漏掉一闪而过的复制 | 首版接受；系统推送 API 不在范围 |
| 图片占内存 | 每端最多 N 条，单条 32 MiB，不落盘 |
| Windows 剪贴板同时只能打开一次 | 每次读写新建上下文 |
