# DeskBaton 文件快传设计

日期：2026-10-19　状态：已实现，硬件验收待实测

主设计见 `2026-10-16-deskbaton-design.md`，配对与链路见 `2026-10-17-pairing-design.md`，本机设置见 `2026-10-17-panel-settings-design.md`。协议借鉴见 `docs/research/2026-10-19-localsend-protocol.md`。冲突时以本文为准。

## 1. 目标

同一个人在局域网里的几台电脑之间倒文件：在面板的设备上右键，或在访达 / 资源管理器里右键「发送到 DeskBaton」，文件就到另一台的「下载」文件夹。对方睡着时先唤醒，传输期间两端都不睡。

产品前提：**单个用户、多台主机、可能多台显示器**。配对即授权，所以默认自动接收；确认模式只作可选项。不考虑多人互传。

## 2. 范围

**做**

- 一次发送多个文件和文件夹：递归，保留相对目录结构和空目录，跳过符号链接
- 接收方式：默认自动接收；设置里可改为「需要确认」，请求挂起等用户处理
- 目标离线时先走唤醒链，最多等 30 秒上线
- 传输期间两端各持一把 `AwakeGuard`
- 独立的 TLS 文件连接，复用 47800 端口与证书指纹校验；控制消息走现有长连接，协议升到 v6
- 多个会话并行；接收时检查磁盘空间
- 面板入口：「电脑」卡片与「设备」页已配对项的右键菜单
- 系统入口：Windows「发送到」；macOS 服务菜单

**不做**

- 续传（中途失败不重传）、请求落盘、跨重启恢复
- 文字消息（剪贴板已实时同步）、一次发给多台
- 拖放到面板（面板失焦即收起，见第 8.1 节）
- Win11 新式一级右键菜单（需 `IExplorerCommand` + 稀疏包身份）、按设备拆分的「发送到」入口
- 传输历史；收到的文件除了「下载」文件夹里那份，不留副本

## 3. 架构

```text
发送方                                   接收方
面板 / 系统菜单 ──路径──▶ FileSessions
                           │ 离线 → Event::WakeFor → 协调器跑唤醒链，等上线 ≤ 30 s
                           │ file_offer（摘要）  ─── 长连接 · 控制通道 ──▶ FileSessions
                           │                                              │ 自动接收 / 用户同意
                           │ ◀──────────── file_accept { token } ─────────┘
                           │ 另拨 TLS → 47800：file_hello { session_id, token }
                           │ 清单 → 逐个文件流式发送 ── 文件连接 · 通道 2 ──▶ 写 .part，边写边算 SHA-256
                           │ ◀──────────── file_result ── 长连接 ─────────┘
```

| 位置 | 职责 |
|---|---|
| `baton-core` | `files` 模块：会话状态机、请求摘要、路径清洗、同名改名、空间判定、拒绝原因；`file_*` 消息；`Event::WakeFor`；`state.toml` 新字段。用假实现单测 |
| `baton-net` | 文件连接：`file_hello` 握手、令牌与已配对校验、通道 2 帧收发；把 `file_*` 控制消息分流给文件会话，不进协调器 |
| `baton-files`（新增） | `FileSessions` 运行时：读写磁盘、`.part` 与改名、系统「下载」文件夹、剩余空间、`AwakeGuard`、进度 |
| `baton-agent` | 组装；把链路的上线 / 下线 / 取消配对通知文件会话 |
| `baton-gui` | 右键菜单、选择框、发送 / 接收卡片、设置项、单实例转发 |
| `baton-macos-sys` | 服务菜单提供者（ObjC），经 FFI 回调把路径交给 Rust |

交棒流程零改动。协调器只新增 `Event::WakeFor(DeviceId)`：跑唤醒链，`NeedsUser` 时照常提示，不进入交棒状态。文件会话不是 `HandoffParticipant`：它随时发生，与交棒无关。

## 4. 会话

### 4.1 状态

发送方：`Waking` →（上线）`Offered` →（`file_accept`）`Sending` → `Done` / `Failed` / `Canceled` / `Rejected`。

接收方：`Pending`（仅确认模式）→ `Receiving` → `Done` / `Failed` / `Canceled`。

会话 id 由发送方生成（53 位随机数，面板以 JavaScript 数字传递），两端按 `(对端, session_id)` 区分。

### 4.2 结束条件

- 同意 / 拒绝 / 任一方 `file_cancel` / 完成。
- **任一端离线**（长连接断开）：所有与该对端的会话立即结束，挂起的作废、传输中的判为失败。
- 取消配对：取消与该设备的所有会话。
- 挂起不设超时。
- 目标离线：唤醒后 30 秒内没上线，判为失败，提示「X 未能唤醒，未发送」。

### 4.3 保持唤醒

从同意（发送方收到 `file_accept`、接收方发出它）到会话结束，两端各持一把 `stay_awake(Duration::MAX)`，与 `power.stay_awake_until` 无关。系统级开关按进程内引用计数共用，与协调器的 guard 叠加。挂起阶段不持有：默认 `peer_offline` 下本来就醒着；`duration` 模式下若睡着，连接断开，请求按 4.2 作废。

## 5. 协议（v6）

`PROTOCOL_VERSION` 升到 6，更新格式稳定性测试。

### 5.1 控制消息（长连接，通道 0）

| 消息 | 方向 | 含义 |
|---|---|---|
| `file_offer { session_id, files, dirs, total_bytes, names }` | 发送 → 接收 | 请求摘要；`names` 为最多 5 个顶层条目名 |
| `file_accept { session_id, token }` | 接收 → 发送 | 同意；`token` 为 32 字节随机数（十六进制），只能用一次 |
| `file_reject { session_id, reason }` | 接收 → 发送 | `reason`：`declined` / `no_space` / `unavailable`（无界面且需要确认）/ `error` |
| `file_cancel { session_id }` | 双向 | 取消挂起或传输中的会话 |
| `file_result { session_id, received, failed }` | 接收 → 发送 | 全部结束后的结果 |

### 5.2 文件连接

发送方收到 `file_accept` 后向接收方的监听端口另拨一条 TLS 连接。

- 首帧（通道 0）为 `file_hello { protocol_version, session_id, token }`，代替 `hello` 与配对握手。
- 接收方校验：对端证书指纹在设备档案里，与该会话的对端一致；令牌匹配且未用过。任一不符就断开。
- 文件连接**不登记为对端连接**：不触发 `PeerOnline` / `PeerOffline`，不参与互拨去重和心跳离线判定。读超时 30 秒。
- 帧格式不变（`len: u32 BE | channel | kind | payload`，单帧 ≤ 1 MiB），数据走通道 `2`：

| kind | 名称 | 负载 |
|---|---|---|
| `0` | Manifest | JSON：`entries[{ path: [段…], kind: "file" \| "dir", size }]`，按发送顺序 |
| `1` | FileBegin | 8 字节大端条目序号 |
| `2` | Chunk | 原始字节，每块 256 KiB |
| `3` | FileEnd | JSON：`{ sha256 }`；为 `null` 表示发送方读取失败或文件中途变了，接收方丢弃该文件 |
| `4` | Done | 空 |

一条连接只服务一个会话，文件按清单顺序串行发送，所以不带 transfer_id。清单可能超过 1 MiB，按多个 Manifest 帧依次拼接。发送方边读边算 SHA-256，接收方边写边算，在 FileEnd 时比对。

文件在请求之后、发送之前被改动（大小与清单不符、读取失败）的，该文件判为失败，继续下一个。

## 6. 接收端落盘

### 6.1 位置

默认是系统「下载」文件夹（macOS `~/Downloads`，Windows 取已知文件夹 `FOLDERID_Downloads`）。可以在设置里改，写入 `state.toml`。

### 6.2 路径清洗

清单里的路径按段给出。接收方逐段处理：

1. 空段、`.`、`..`、含 `/` 或 NUL 的段 → 整个会话判为错误。`\` 在 Mac 上是合法文件名字符，按下一步处理。
2. 按**接收方平台**替换非法字符：
   - Windows：`< > : " / \ | ? *` 换成全角 `＜ ＞ ： ＂ ／ ＼ ｜ ？ ＊`；控制字符删掉；去掉结尾的空格和点；`CON` `PRN` `AUX` `NUL` `COM1–9` `LPT1–9`（不分大小写、忽略扩展名）后加 `_`。
   - macOS：控制字符删掉。
3. 处理后为空的段换成 `_`。

### 6.3 写入与冲突

- 只对**顶层条目**做冲突改名：`报告.pdf` → `报告 (1).pdf`，`照片/` → `照片 (1)/`。新建的文件夹里不会再有冲突。用「不存在才创建」的方式占名，避免与并行会话撞名。
- 每个文件先写 `名称.part`，校验通过后改成正式名称；失败就删掉 `.part`。
- 不覆盖已有文件，也不逐个询问。

### 6.4 磁盘空间

同意时（含自动接收）要求接收目录所在卷的剩余空间 ≥ 本次总大小 + 全部进行中接收会话尚未写完的量（不区分所在卷，宁可多扣），否则回 `file_reject { reason: "no_space" }`，提示「磁盘空间不足，未接收来自 X 的文件」。

## 7. 设置

写入 `state.toml`，继续 `deny_unknown_fields`、读-改-写。

| 项 | 字段 | 默认 | 作用 |
|---|---|---|---|
| 自动接收 | `file_auto_accept` | 开 | 关：请求挂起，等用户在面板上处理 |
| 接收位置 | `file_receive_dir` | 空 | 空表示系统「下载」文件夹 |

无界面 `deskbaton` 读同样的字段。它没有确认界面：`file_auto_accept` 为关时一律回 `unavailable`。

## 8. 面板

### 8.1 发送入口

- 「电脑」卡片和「设备」页的已配对项都支持右键菜单：「发送文件…」「发送文件夹…」。本机那一项和未配对设备不出现该菜单；离线设备可点，按 4.2 先唤醒。
- 选择框打开期间暂停「失焦即收起」，关闭后恢复。
- 不做拖放：从访达 / 资源管理器按住文件时面板已失焦收起。

### 8.2 发送方卡片

- `Waking`：「正在唤醒 X…」+「取消」。
- `Offered`（对方需要确认时）：「等待 X 接收 · N 个文件 · 大小」+「切过去」（走 `Event::HandoffTo`）+「取消」。
- `Sending`：进度条（按已写入连接的字节数）+「取消」。
- 结束：「已送达 N 个」或「已送达 3 / 5 个，其余失败」，约 5 秒后收起；被拒绝时显示原因。

### 8.3 接收方

「本机可见」= 本机持棒，或 `display.mode = "none"`。

| 模式 | 本机可见 | 本机不可见 |
|---|---|---|
| 需要确认 | 请求到达即弹出面板，定位到请求卡片（来源、文件数、总大小、前几个名字，「拒绝 / 接收」） | 系统通知 +「设备」tab 标记；本机接棒时弹出面板并定位到请求 |
| 自动接收 | 收完发系统通知「已收到 N 个文件」，点击在访达 / 资源管理器中定位 | 同左；本机接棒时弹出面板，提示「刚收到 N 个文件 · 在访达中显示」，看过或超过 10 分钟后不再弹 |

传输中的接收卡片显示进度和「取消」。

### 8.4 系统入口

- **Windows**：安装器在 `%APPDATA%\Microsoft\Windows\SendTo\` 放 `DeskBaton.lnk`，目标为 `deskbaton-gui.exe --send`，卸载时删除。资源管理器一次性传入多选路径。面板已在运行时由 `tauri-plugin-single-instance` 把参数转给它。Win11 上位于「显示更多选项」。
- **macOS**：`Info.plist` 声明 `NSServices`（`NSSendFileTypes = public.item`），`baton-macos-sys/native` 实现服务提供者，经 FFI 回调把路径交给 Rust。
- **选目标**：只有一台已配对设备时直接发给它；有多台时弹出面板，列出已配对设备，上次发送的设备排第一并默认选中。没有已配对设备时提示「还没有配对的设备」。

## 9. 失败

文件快传失败不影响交棒；提示走现有 `Notifier`。

| 场景 | 处理 |
|---|---|
| 唤醒后 30 秒没上线 | 发送方失败，提示「X 未能唤醒，未发送」 |
| 长连接断开 | 与该对端的会话全部结束；传输中的判为失败，删掉 `.part` |
| 文件连接断开或读超时 | 该会话失败，已校验的文件保留 |
| 单个文件读失败 / 被改动 / 校验不符 | 该文件失败，继续下一个 |
| 路径含 `..` 等 | 整个会话判为错误，不落盘 |
| 磁盘空间不足 | `no_space` 拒绝 |
| 写入失败（权限、磁盘满） | 该会话失败，删掉 `.part` |
| 令牌不符、未配对设备连文件连接 | 断开，只记日志 |
| 对端协议版本 < 6 | 握手不通过（与现有版本校验一致） |

## 10. 测试

- `baton-core`：会话状态机各条结束路径（同意、拒绝、取消、离线作废、唤醒超时）；摘要；路径清洗（全角替换、保留名、结尾空格和点、`..` 判错）；顶层改名序号；空间判定扣除进行中会话；`state.toml` 新字段的默认值与兼容。
- `baton-net`：`file_hello` 令牌只能用一次；未配对指纹、指纹与会话对端不符时断开；文件连接不触发上线 / 下线；Manifest 分帧拼接；格式稳定性测试覆盖 v6 新消息。
- 回环：两个 agent 互发一个含空目录与多个文件的文件夹；同名时改名；中途断开时 `.part` 被删、已完成的文件保留；确认模式下拒绝。
- CI 不碰真实的「下载」文件夹，用临时目录。

硬件验收（手动，🔧，用户确认后才打勾）：

1. Mac 在面板上右键 Windows「发送文件…」选几个文件，Windows「下载」里立刻出现，名字里的 `:` `?` 变成全角。
2. Windows 资源管理器多选文件和一个文件夹 →「发送到 → DeskBaton」，Mac「下载」里结构一致。
3. Mac 访达右键 → 服务 / 快速操作里出现 DeskBaton，发送成功。
4. 合盖 Mac 睡着时从 Windows 发送，Mac 被唤醒并收完；传输 5 GB 期间两端都不睡。
5. 改为「需要确认」后从 Mac 发给 Windows，点「切过去」，Windows 上面板自动弹出并定位到请求，接收成功。
6. 传输中按热键交棒，画面和键鼠照常切换，传输不中断。

## 11. 风险

| 风险 | 应对 |
|---|---|
| macOS 服务菜单默认不显示、或登记要等一段时间 | 列为 🔧 实测；不行再评估 Automator 快速操作或 Finder 扩展 |
| 文件连接与长连接共用 Wi-Fi 带宽，交棒消息变慢 | 分属两条 TCP，系统按连接调度，不再排在同一发送缓冲后；验收第 6 项实测 |
| 全角替换后发回 Mac 不还原 | 接受；名字仍可读 |
| `.part` 在进程崩溃后残留 | 首版接受；文件名后缀能看出是半截文件 |
| 自动接收误发大文件 | 发送方卡片随时可取消；磁盘空间检查兜底 |
| 并行会话同时抢占同名 | 「不存在才创建」占名 |
